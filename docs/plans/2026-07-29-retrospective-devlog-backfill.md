# Retrospective Devlog Backfill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a one-time monthly-ish retrospective devlog backfill that makes the known project history read consistently without inventing exact daily progress.

**Architecture:** Use a curated docs-only content pass under `docs/dev/journal/`, backed by `docs/dev/project/history.md`, ADRs, feature pages, notes, and commit date sanity checks. Existing journal/devlog generation scripts produce `docs/dev/journal/index.md` and `docs/dev/devlog.md`; no automation, runtime, or OpenCode behavior changes are needed.

**Tech Stack:** Markdown, existing Node.js ESM docs scripts, VitePress, Git history inspection.

## Global Constraints

- Use a one-time curated content pass, not an automation pipeline.
- The existing daily devlog automation remains forward-looking.
- Dates may be approximate anchors when the known history is phase-based, but the prose must make the work read as an arc or “by this point” milestone instead of claiming exact same-day completion.
- Backfill entries may use only evidence from the repository.
- The content must not invent ungrounded features, outcomes, authors, motivations, or dates.
- If the available sources cannot support a proposed entry, skip it rather than filling every calendar month.
- Preserve existing non-empty 2025-09 and 2026-02 journal/devlog entries.
- Each new or rewritten backfill entry uses the daily devlog entry shape: frontmatter, `# YYYY-MM-DD`, and one short narrative paragraph.
- The paragraph should be brief, narrative, and contextual.
- It must not include `## Today`, `## Decisions`, `## Tomorrow`, bullet lists, commit hashes, author lists, raw file lists, or a chronological commit summary.
- If source review contradicts the proposed entry set or an entry would require speculation, the implementer should stop with `NEEDS_CONTEXT` instead of fabricating a paragraph.
- If docs generation or build fails, debug the failure separately and do not hide it by editing generated output by hand.
- No production C++/Lua/runtime changes are required.
- Do not add npm dependencies or change docs script behavior.

- [ ] **Step 8: Validate entry shape and legacy preservation**

Run this focused check from the repository root:

```bash
python3 - <<'PY'
from pathlib import Path

entries = [
    'docs/dev/journal/2025-10-01.md',
    'docs/dev/journal/2026-03-18.md',
    'docs/dev/journal/2026-04-16.md',
    'docs/dev/journal/2026-05-08.md',
    'docs/dev/journal/2026-06-15.md',
    'docs/dev/journal/2026-07-14.md',
]

for entry in entries:
    path = Path(entry)
    text = path.read_text()
    date = path.stem
    assert text.startswith('---\n'), entry
    assert 'type: journal\n' in text, entry
    assert 'tags: [journal, devlog]\n' in text, entry
    assert f'created: {date}\n' in text, entry
    marker = f'\n# {date}\n\n'
    assert marker in text, entry
    body = text.split(marker, 1)[1].strip()
    assert body, entry
    assert '\n\n' not in body, entry
    assert '\n- ' not in body and not body.startswith('- '), entry
    assert '## ' not in body, entry
    for forbidden in ['commit ', 'commits ', 'author', 'hash']:
        assert forbidden not in body.lower(), (entry, forbidden)

legacy_changed = [
    name for name in [
        'docs/dev/journal/2025-09-16.md',
        'docs/dev/journal/2025-09-17.md',
        'docs/dev/journal/2025-09-24.md',
        'docs/dev/journal/2026-02-08.md',
        'docs/dev/journal/2026-02-09.md',
        'docs/dev/journal/2026-02-16.md',
    ]
    if name in __import__('subprocess').check_output(['git', 'diff', '--name-only'], text=True).splitlines()
]
assert not legacy_changed, legacy_changed
print('retrospective devlog entry shape ok')
PY
```

Expected: prints `retrospective devlog entry shape ok`.
